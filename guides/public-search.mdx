Mutasib includes a built-in public marketplace that lets customers discover your shop and browse your products without needing a Mutasib account. This page explains how to make your shop and products visible in search, how the public API endpoints work, and how to enable location-based discovery so nearby customers can find you.

## Requirements for appearing in search

Your shop and products must meet a few conditions before they appear in public search results.

**Shop-level requirements:**
- Your shop must be approved by Mutasib (`is_approved: true`).
- Your shop must be active (`is_active: true`).
- Your plan must be Starter or Pro — Free plan shops are not listed in the public marketplace.

**Product-level requirements:**
- Each product must be individually marked as public (`is_public: true`). Products are private by default.
- Your plan determines how many products you can make public simultaneously (see the public summary endpoint below).

<Note>
  Pro plan shops receive higher placement in search results and may be featured in curated sections of the marketplace.
</Note>

## Making products public

Products are private by default. You control visibility product by product, or in bulk.

### Toggle a single product

Send a `POST` request to the toggle-public endpoint for a specific product. Each call flips the `is_public` flag — if the product is currently private it becomes public, and vice versa.

```bash
curl -X POST https://api.mutasib.com/api/v1/shops/42/products/17/toggle-public \
  -H "Authorization: Bearer <your_token>"
```

### Update visibility in bulk

To set the visibility of multiple products at once, use the batch-visibility endpoint:

<CodeGroup>
```bash cURL
curl -X POST https://api.mutasib.com/api/v1/shops/42/products/batch-visibility \
  -H "Authorization: Bearer <your_token>" \
  -H "Content-Type: application/json" \
  -d '{
    "product_ids": [17, 23, 31],
    "is_public": true
  }'
```

```python Python
import requests

requests.post(
    "https://api.mutasib.com/api/v1/shops/42/products/batch-visibility",
    headers={"Authorization": "Bearer <your_token>"},
    json={"product_ids": [17, 23, 31], "is_public": True},
)
```

```js JavaScript
await fetch("https://api.mutasib.com/api/v1/shops/42/products/batch-visibility", {
  method: "POST",
  headers: {
    Authorization: "Bearer <your_token>",
    "Content-Type": "application/json",
  },
  body: JSON.stringify({ product_ids: [17, 23, 31], is_public: true }),
});
```
</CodeGroup>

### Checking your public product quota

Your plan caps how many products can be public at once. Use the public-summary endpoint to check your current usage against the limit before making bulk changes.

```bash
curl https://api.mutasib.com/api/v1/shops/42/products/public-summary \
  -H "Authorization: Bearer <your_token>"
```

```json
{
  "public_count": 34,
  "plan_limit": 50
}
```

## Public search endpoints

All of the endpoints in this section are **unauthenticated** — no token required. They are intended for customer-facing surfaces such as storefronts, mobile apps, or embed widgets.

### Search across all shops

Use the main search endpoint to find products matching a query, optionally filtered by category, price range, or a specific shop.

```bash
# Search for "milk" in the grocery category, priced between 0 and 50
curl "https://api.mutasib.com/api/v1/public/search/?q=milk&category=grocery&min_price=0&max_price=50"

# Search within a specific shop
curl "https://api.mutasib.com/api/v1/public/search/?q=bread&shop_id=42"
```

All query parameters are optional — omitting `q` returns all visible products (useful for browsing by category).

### List all visible shops

```bash
curl https://api.mutasib.com/api/v1/public/shops/
```

Returns all approved, active shops that have opted in to public visibility. The response is paginated.

### Get a single shop's details

```bash
curl https://api.mutasib.com/api/v1/public/shops/42/
```

### List a shop's public products

```bash
curl https://api.mutasib.com/api/v1/public/shops/42/products/
```

Returns only the products where `is_public: true`. Private products are never included in this response, regardless of the caller.

## Nearby shop discovery

Customers can search for shops within a geographic radius using the nearby endpoint. This is useful for local discovery features in mobile apps or maps.

```bash
# Find all shops within 10 km of Algiers city centre
curl "https://api.mutasib.com/api/v1/public/shops/nearby/?lat=36.7&lng=3.05&radius=10"
```

| Parameter | Type | Default | Description |
|---|---|---|---|
| `lat` | float | — | Latitude of the search origin |
| `lng` | float | — | Longitude of the search origin |
| `radius` | float | `10` | Search radius in kilometres |

The response returns shops sorted by `distance_km` in ascending order, so the closest shop appears first.

For your shop to appear in nearby results, it must have its `latitude` and `longitude` fields set.

## Setting your shop's location

Update your shop's coordinates with a `PATCH` request. You only need to do this once (or whenever your shop moves).

```bash
curl -X PATCH https://api.mutasib.com/api/v1/shops/42 \
  -H "Authorization: Bearer <your_token>" \
  -H "Content-Type: application/json" \
  -d '{
    "latitude": 36.7372,
    "longitude": 3.0865
  }'
```

Once coordinates are saved, your shop will appear in nearby searches automatically — no further action needed.

<Accordion title="Tips for better search visibility">
  - **Write descriptive product names.** The search index matches against product names and descriptions, so clear names like "Full-Fat Labneh 500g" rank better than "LBN-500".
  - **Use consistent categories.** Products grouped under recognised categories (e.g. `dairy`, `bakery`, `beverages`) benefit from category-filtered searches.
  - **Keep prices up to date.** Customers often filter by price range — stale prices lead to confusion and abandoned visits.
  - **Add your location.** Even if you don't have a delivery service, appearing in nearby searches drives walk-in traffic.
</Accordion>
