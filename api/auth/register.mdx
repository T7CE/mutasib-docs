---
title: "Create a New Mutasib Account with the Register API"
sidebarTitle: "Register"
description: "Register a new Mutasib user, verify your email address, and resend the verification link if it expires — all through the registration API."
---

Registration creates a new user account in Mutasib. Once you submit your details, the API provisions your account and immediately dispatches a verification email to the address you provided. You must complete email verification before you can log in for the first time.

## Endpoint

```
POST /api/v1/auth/register
```

## Request Body

<ParamField body="email" type="string" required>
  The email address for the new account. Must be a valid email format and unique across all Mutasib users.
</ParamField>

<ParamField body="username" type="string" required>
  A display name for the account. Usernames must be unique and can contain letters, numbers, and underscores.
</ParamField>

<ParamField body="password" type="string" required>
  The account password. Use a strong password of at least eight characters.
</ParamField>

<ParamField body="role" type="string">
  The role to assign to the new user. Defaults to `shopowner` when omitted. Accepted values are `shopowner` and `cashier`. A `shopowner` has full access to all shop management features; a `cashier` has access limited to point-of-sale operations.
</ParamField>

## Example Request

<CodeGroup>

```bash curl
curl --request POST \
  --url https://api.mutasib.com/api/v1/auth/register \
  --header 'Content-Type: application/json' \
  --data '{
    "email": "sara@example.com",
    "username": "sara_shop",
    "password": "S3cur3P@ssw0rd!",
    "role": "shopowner"
  }'
```

```json Request Body
{
  "email": "sara@example.com",
  "username": "sara_shop",
  "password": "S3cur3P@ssw0rd!",
  "role": "shopowner"
}
```

</CodeGroup>

## Response — 201 Created

A successful registration returns a plain success object confirming that the account was created and the verification email was dispatched.

```json
{
  "message": "User registered successfully. Please check your email to verify your account."
}
```

## Email Verification

After registration, Mutasib sends a verification link to the email address you provided. The link embeds a short-lived token. To activate your account and receive your access and refresh tokens, make the following request with that token.

```
POST /api/v1/auth/verify-email?token=TOKEN
```

```bash
curl --request POST \
  --url 'https://api.mutasib.com/api/v1/auth/verify-email?token=<verification_token>'
```

### Response — 200 OK

A successful verification returns a `TokenOut` object. Store the `access` token for use in the `Authorization: Bearer` header and the `refresh` token to obtain new access tokens when the current one expires.

```json
{
  "access": "eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9...",
  "refresh": "eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "bearer"
}
```

<ResponseField name="access" type="string">
  A short-lived token. Pass this value in the `Authorization: Bearer` header for all authenticated requests.
</ResponseField>

<ResponseField name="refresh" type="string">
  A longer-lived token. Use it to obtain a fresh access token via the token refresh endpoint without requiring the user to log in again.
</ResponseField>

<ResponseField name="token_type" type="string">
  Always `"bearer"`. Indicates the token scheme to use in the `Authorization` header.
</ResponseField>

## Resend Verification Email

If the verification email did not arrive or the link has expired, you can request a new one using the resend endpoint.

```
POST /api/v1/auth/resend-verification?email=EMAIL
```

```bash
curl --request POST \
  --url 'https://api.mutasib.com/api/v1/auth/resend-verification?email=sara%40example.com'
```

### Response — 200 OK

```json
{
  "message": "Verification email resent. Please check your inbox."
}
```

<Note>
  You cannot log in until your email address is verified. If the verification email does not arrive within a few minutes, check your spam folder. Use the resend endpoint above to get a fresh link — do not re-register with the same address.
</Note>
