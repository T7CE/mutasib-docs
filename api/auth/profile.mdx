The profile endpoints give you full control over your own user record. You can read your current profile, update your display name or email address, change your password, trigger a password reset by email, and permanently delete your account. All endpoints in this section require a valid Bearer token unless otherwise noted.

---

## Get Your Profile

Fetch the full profile for the currently authenticated user by calling the endpoint below with your access token.

```
GET /api/v1/auth/me
```

```bash
curl --request GET \
  --url https://api.mutasib.com/api/v1/auth/me \
  --header 'Authorization: Bearer eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9...'
```

### Response — 200 OK

```json
{
  "id": "usr_9f3a1b2c4d5e",
  "email": "sara@example.com",
  "username": "sara_shop",
  "role": "shopowner",
  "is_active": true,
  "is_email_verified": true,
  "created_at": "2024-03-15T09:22:41Z",
  "updated_at": "2024-11-02T14:05:18Z"
}
```

<ResponseField name="id" type="string">
  The unique identifier for the user account. Use this value when referencing the user in other API calls.
</ResponseField>

<ResponseField name="email" type="string">
  The email address associated with the account. Changing this value triggers a new verification email.
</ResponseField>

<ResponseField name="username" type="string">
  The display name shown across the Mutasib dashboard and reports.
</ResponseField>

<ResponseField name="role" type="string">
  The user's assigned role. Either `shopowner` or `cashier`.
</ResponseField>

<ResponseField name="is_active" type="boolean">
  `true` if the account is active. A `false` value means the account has been deactivated — either by the user requesting deletion or by an administrator.
</ResponseField>

<ResponseField name="is_email_verified" type="boolean">
  `true` if the user has confirmed their email address via the verification link sent at registration.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp of when the account was first created.
</ResponseField>

<ResponseField name="updated_at" type="string">
  ISO 8601 timestamp of the most recent update to any profile field.
</ResponseField>

## Update Your Profile

Update your display name or email address. Only include the fields you want to change; omitted fields are left untouched. The endpoint returns the full updated user object.

```
PATCH /api/v1/auth/me
```

<ParamField body="name" type="string">
  A new username / display name for the account.
</ParamField>

<ParamField body="email" type="string">
  A new email address. Updating this field triggers a verification email to the new address. Your old address remains active until the new one is verified.
</ParamField>

```bash
curl --request PATCH \
  --url https://api.mutasib.com/api/v1/auth/me \
  --header 'Authorization: Bearer eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9...' \
  --header 'Content-Type: application/json' \
  --data '{
    "name": "sara_boutique",
    "email": "sara.boutique@example.com"
  }'
```

**Response — 200 OK**

The updated user object is returned immediately so you can reflect the changes in your application without a separate profile fetch.

```json
{
  "id": "usr_9f3a1b2c4d5e",
  "email": "sara.boutique@example.com",
  "username": "sara_boutique",
  "role": "shopowner",
  "is_active": true,
  "is_email_verified": true,
  "created_at": "2024-03-15T09:22:41Z",
  "updated_at": "2024-11-02T15:30:00Z"
}
```

## Change Password

Update the password for the currently authenticated account. You must supply the existing password to authorize the change.

```
POST /api/v1/auth/change-password
```

<ParamField body="old_password" type="string" required>
  Your current password. Used to verify your identity before the change is applied.
</ParamField>

<ParamField body="new_password" type="string" required>
  The password you want to switch to. Choose a strong password of at least eight characters.
</ParamField>

```bash
curl --request POST \
  --url https://api.mutasib.com/api/v1/auth/change-password \
  --header 'Authorization: Bearer eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9...' \
  --header 'Content-Type: application/json' \
  --data '{
    "old_password": "S3cur3P@ssw0rd!",
    "new_password": "N3wStr0ng#Pass99"
  }'
```

**Response — 200 OK**

```json
{
  "message": "Password changed successfully."
}
```

## Forgot Password

If you cannot log in because you have forgotten your password, use this two-step flow to set a new one. Step one sends a reset token to your email; step two consumes that token to set the new password.

<Steps>
  <Step title="Request a Password Reset Email">
    Call the forgot-password endpoint with your registered email address. Mutasib sends a reset link containing a `uid` and a `token` to that address.

    ```
    POST /api/v1/auth/forgot-password
    ```

    <ParamField body="email" type="string" required>
      The email address of the account you need to recover.
    </ParamField>

    ```bash
    curl --request POST \
      --url https://api.mutasib.com/api/v1/auth/forgot-password \
      --header 'Content-Type: application/json' \
      --data '{
        "email": "sara@example.com"
      }'
    ```

    **Response — 200 OK**

    ```json
    {
      "message": "If that email address is registered, a password reset link has been sent."
    }
    ```

    The API always returns `200 OK` for this request regardless of whether the email address exists, to prevent account enumeration.
  </Step>

  <Step title="Submit the New Password">
    Extract the `uid` and `token` values from the reset link in the email, then call the reset endpoint.

    ```
    POST /api/v1/auth/reset-password
    ```

    <ParamField body="uid" type="string" required>
      The user identifier embedded in the password reset link.
    </ParamField>

    <ParamField body="token" type="string" required>
      The time-limited reset token embedded in the password reset link. Tokens expire after 1 hour.
    </ParamField>

    <ParamField body="new_password" type="string" required>
      The new password to set on the account.
    </ParamField>

    ```bash
    curl --request POST \
      --url https://api.mutasib.com/api/v1/auth/reset-password \
      --header 'Content-Type: application/json' \
      --data '{
        "uid": "usr_9f3a1b2c4d5e",
        "token": "bWFnaWMtcmVzZXQtdG9rZW4tc2FtcGxl",
        "new_password": "N3wStr0ng#Pass99"
      }'
    ```

    **Response — 200 OK**

    ```json
    {
      "message": "Password has been reset successfully. You can now log in with your new password."
    }
    ```
  </Step>
</Steps>

## Delete Account

Permanently remove your Mutasib account. This operation performs a soft-delete: your personal information (name, email, and other PII) is anonymized, your account is deactivated, and you can no longer log in. An anonymized audit record is retained to preserve transaction and compliance history.

```
POST /api/v1/auth/delete-account
```

<ParamField body="password" type="string" required>
  Your current password, required to confirm that you are authorizing this deletion intentionally.
</ParamField>

```bash
curl --request POST \
  --url https://api.mutasib.com/api/v1/auth/delete-account \
  --header 'Authorization: Bearer eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9...' \
  --header 'Content-Type: application/json' \
  --data '{
    "password": "N3wStr0ng#Pass99"
  }'
```

**Response — 200 OK**

```json
{
  "message": "Your account has been permanently deleted. Personal data has been anonymized."
}
```

<Warning>
  Account deletion is irreversible. Once confirmed, your login credentials stop working immediately and your personal data cannot be recovered. If you manage a shop with active staff or ongoing transactions, transfer ownership or settle outstanding records before deleting your account.
</Warning>

## Set a User's Role (Admin Only)

An administrator can change the role of any user account. Pass the target user's ID as a path parameter and the desired role as a query parameter.

```
PUT /api/v1/auth/users/{user_id}/role?role=ROLE
```

<ParamField path="user_id" type="string" required>
  The unique ID of the user whose role you want to change.
</ParamField>

<ParamField query="role" type="string" required>
  The new role to assign. Accepted values: `shopowner`, `cashier`.
</ParamField>

```bash
curl --request PUT \
  --url 'https://api.mutasib.com/api/v1/auth/users/usr_9f3a1b2c4d5e/role?role=cashier' \
  --header 'Authorization: Bearer eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9...'
```

**Response — 200 OK**

```json
{
  "message": "User role updated to cashier."
}
```
