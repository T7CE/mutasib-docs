Mutasib offers three subscription tiers for shops: `free`, `starter`, and `pro`. The Plans API lets you check a shop's current plan, start a free trial, redirect users to a hosted checkout to upgrade, and cancel an active subscription. Plan changes take effect automatically after payment or trial activation — no manual intervention is required.

---

## Get current plan

<br />

`GET /api/v1/shops/{shop_id}/plan`

Returns the shop's current subscription plan, the features it unlocks, and the expiry timestamp if the plan is time-limited (trial or paid subscription).

```bash
curl https://api.mutasib.com/api/v1/shops/42/plan \
  -H "Authorization: Bearer <your_token>"
```

**Response**

<ResponseField name="plan" type="string">
  The active plan name: `"free"`, `"starter"`, or `"pro"`.
</ResponseField>

<ResponseField name="plan_features" type="object">
  A map of feature flags and limits enabled by the current plan.
  <Expandable title="properties">
    <ResponseField name="max_cashiers" type="integer">
      Maximum number of cashier staff members allowed on this plan.
    </ResponseField>
    <ResponseField name="low_stock_alerts" type="boolean">
      Whether low-stock email and push alerts are available.
    </ResponseField>
    <ResponseField name="email_reports" type="boolean">
      Whether scheduled email reports are available.
    </ResponseField>
    <ResponseField name="public_storefront" type="boolean">
      Whether the shop can be listed in public search results.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="plan_expires_at" type="string | null">
  ISO 8601 timestamp of when the current paid plan or trial expires. `null` for the `free` plan, which never expires.
</ResponseField>

## Start a free trial

<br />

`POST /api/v1/shops/{shop_id}/plan/trial`

Activates a 14-day Starter plan trial for the shop. The trial grants all Starter plan features immediately. Each shop can only start one free trial — calling this endpoint again after the trial has been used returns a `409 Conflict`.

```bash
curl -X POST https://api.mutasib.com/api/v1/shops/42/plan/trial \
  -H "Authorization: Bearer <your_token>"
```

Returns `200 OK` with the updated plan object (`plan`, `plan_features`, `plan_expires_at`). The `plan` field will read `"starter"` and `plan_expires_at` will be set 14 days from now.

<Note>
  The free trial is available once per shop. If the shop has previously activated a trial, this endpoint returns `409 Conflict` with an error message explaining that the trial has already been used.
</Note>

## Upgrade via checkout

<br />

`POST /api/v1/payments/checkout?shop_id={shop_id}&plan={plan}`

Initiates a hosted checkout session for upgrading the shop to a paid plan. Payments are processed securely by **Lemon Squeezy** — Mutasib never handles raw card data.

### Query parameters

<ParamField query="shop_id" type="integer" required>
  The ID of the shop you are upgrading.
</ParamField>

<ParamField query="plan" type="string" required>
  The plan to upgrade to. Accepted values: `starter`, `pro`.
</ParamField>

```bash
curl -X POST "https://api.mutasib.com/api/v1/payments/checkout?shop_id=42&plan=pro" \
  -H "Authorization: Bearer <your_token>"
```

**Response**

<ResponseField name="checkout_url" type="string">
  The Lemon Squeezy hosted checkout URL. Redirect the user's browser to this URL to complete payment.
</ResponseField>

After the user completes payment on Lemon Squeezy's checkout page, a webhook updates the shop's plan automatically. The user is returned to a success page hosted by Mutasib.

<Note>
  The plan change does **not** take effect immediately upon calling this endpoint — it takes effect only after the payment webhook is received and processed. Redirect the user to `checkout_url` and wait for the webhook before reflecting the new plan in your UI.
</Note>

## Cancel a subscription

<br />

`POST /api/v1/shops/{shop_id}/plan/cancel`

Cancels the shop's active paid subscription. The shop retains all plan features until the subscription's `plan_expires_at` date; after that point it reverts to the `free` plan automatically.

```bash
curl -X POST https://api.mutasib.com/api/v1/shops/42/plan/cancel \
  -H "Authorization: Bearer <your_token>"
```

Returns `200 OK` with the updated plan object. The `plan` field remains unchanged until the expiry date passes.

<Warning>
  Cancelling a subscription is immediate and cannot be undone through the API. If you cancel by mistake, you will need to go through the checkout flow again to re-subscribe.
</Warning>

## Plan names reference

Use the following lowercase string values when referring to plans in API requests.

| Plan | Value in API | Description |
|------|-------------|-------------|
| Free | `"free"` | Default plan. 1 cashier, no alerts, no public listing. |
| Starter | `"starter"` | Up to 5 cashiers, low-stock alerts, public storefront. |
| Pro | `"pro"` | Unlimited cashiers, all Starter features, email reports, priority support. |

<Tip>
  Use the [Start a free trial](#start-a-free-trial) endpoint to let your users experience Starter features risk-free before asking them to enter payment details.
</Tip>
