---
title: "Staff Invitations API: Add Cashiers to Your Shop"
sidebarTitle: "Staff & Invitations"
description: "Invite, list, and remove staff members, and manage pending invitations for your Mutasib shop using token-based invite links."
---

Mutasib uses a token-based invitation flow to add staff to your shop. You create an invitation (optionally targeting a specific email address), share the resulting token or link with your staff member, and they accept it with their authenticated Mutasib account. Invitations expire after a configurable window and can be revoked at any time before they are used.

---

## Create an invitation

<br />

`POST /api/v1/shops/{shop_id}/invitations`

Generates a new invitation token that a staff member can use to join your shop. You can target a specific email address or leave it blank to create an open-link invitation.

### Request body

<ParamField body="role" type="string" default='"cashier"'>
  The role to assign to the staff member upon accepting. Currently supported value: `"cashier"`.
</ParamField>

<ParamField body="email" type="string" default='""'>
  Optional email address to associate with this invitation. When provided, only a user with this email can accept the invitation.
</ParamField>

<ParamField body="expires_in_hours" type="integer" default="72">
  Number of hours until the invitation expires. Defaults to `72` (3 days).
</ParamField>

```bash
curl -X POST https://api.mutasib.com/api/v1/shops/42/invitations \
  -H "Authorization: Bearer <your_token>" \
  -H "Content-Type: application/json" \
  -d '{
    "role": "cashier",
    "email": "sarah@example.com",
    "expires_in_hours": 48
  }'
```

Returns `201 Created` with an [InvitationOut](#invitationout-fields) object containing the `token` your staff member needs to accept the invitation.

## List invitations

<br />

`GET /api/v1/shops/{shop_id}/invitations`

Returns all invitations for the shop, including pending, used, and expired ones. Use this to audit outstanding invites or clean up old ones.

```bash
curl https://api.mutasib.com/api/v1/shops/42/invitations \
  -H "Authorization: Bearer <your_token>"
```

Returns `200 OK` with an array of [InvitationOut](#invitationout-fields) objects.

---

## Revoke an invitation

<br />

`DELETE /api/v1/shops/{shop_id}/invitations/{invitation_id}`

Immediately invalidates a pending invitation. Staff members who received this invitation link will no longer be able to use it. Already-accepted invitations cannot be revoked (remove the staff member directly instead).

```bash
curl -X DELETE https://api.mutasib.com/api/v1/shops/42/invitations/17 \
  -H "Authorization: Bearer <your_token>"
```

Returns `204 No Content` on success.

## Look up an invitation by token

<br />

`GET /api/v1/shops/invite/lookup/?token={token}`

Retrieves the details of an invitation using its token. This endpoint is **public** — no authentication is required — so your frontend can display shop name, role, and expiry information to the prospective staff member before they log in.

```bash
curl "https://api.mutasib.com/api/v1/shops/invite/lookup/?token=abc123xyz"
```

Returns `200 OK` with an [InvitationOut](#invitationout-fields) object. Returns `404 Not Found` if the token does not exist, and `410 Gone` if the invitation has already expired or been used.

## Accept an invitation

<br />

`POST /api/v1/shops/invite/accept`

Accepts a pending invitation and adds the authenticated user to the shop as a staff member with the role specified in the invitation. The user must be authenticated — have them log in before calling this endpoint.

### Request body

<ParamField body="token" type="string" required>
  The invitation token obtained from the invitation link or the lookup endpoint.
</ParamField>

```bash
curl -X POST https://api.mutasib.com/api/v1/shops/invite/accept \
  -H "Authorization: Bearer <staff_member_token>" \
  -H "Content-Type: application/json" \
  -d '{ "token": "abc123xyz" }'
```

Returns `200 OK` with a [StaffMemberOut](#staffmemberout-fields) object representing the newly created staff membership.

<Note>
  If the invitation was created with a specific email, the authenticated user's email must match that address. Mismatched emails return a `403 Forbidden` error.
</Note>

## List staff members

<br />

`GET /api/v1/shops/{shop_id}/staff`

Returns all current staff members of the shop. This does not include pending (unaccepted) invitations — use [List invitations](#list-invitations) for those.

```bash
curl https://api.mutasib.com/api/v1/shops/42/staff \
  -H "Authorization: Bearer <your_token>"
```

Returns `200 OK` with an array of [StaffMemberOut](#staffmemberout-fields) objects.

---

## Remove a staff member

<br />

`DELETE /api/v1/shops/{shop_id}/staff/{staff_id}`

Removes a staff member from the shop. The removed user loses all access to the shop immediately. You cannot remove yourself (the owner) using this endpoint.

```bash
curl -X DELETE https://api.mutasib.com/api/v1/shops/42/staff/9 \
  -H "Authorization: Bearer <your_token>"
```

Returns `204 No Content` on success.

## InvitationOut fields

<ResponseField name="id" type="integer">
  Unique numeric ID of the invitation record.
</ResponseField>

<ResponseField name="token" type="string">
  The secret token string that the staff member uses to accept the invitation.
</ResponseField>

<ResponseField name="shop_id" type="integer">
  ID of the shop this invitation belongs to.
</ResponseField>

<ResponseField name="shop_name" type="string">
  Display name of the shop, included for convenience when looking up by token.
</ResponseField>

<ResponseField name="role" type="string">
  The role the invitee will receive upon acceptance (e.g., `"cashier"`).
</ResponseField>

<ResponseField name="email" type="string">
  The email address the invitation is restricted to, or an empty string for open invitations.
</ResponseField>

<ResponseField name="is_used" type="boolean">
  `true` if the invitation has already been accepted.
</ResponseField>

<ResponseField name="is_expired" type="boolean">
  `true` if the invitation has passed its `expires_at` time.
</ResponseField>

<ResponseField name="expires_at" type="string">
  ISO 8601 timestamp after which the invitation can no longer be accepted.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp of when the invitation was created.
</ResponseField>

---

## StaffMemberOut fields

<ResponseField name="id" type="integer">
  Unique numeric ID of the staff membership record.
</ResponseField>

<ResponseField name="user_id" type="integer">
  The Mutasib user ID of the staff member.
</ResponseField>

<ResponseField name="email" type="string">
  The staff member's email address.
</ResponseField>

<ResponseField name="username" type="string">
  The staff member's Mutasib username.
</ResponseField>

<ResponseField name="role" type="string">
  The role assigned to this staff member within the shop (e.g., `"cashier"`).
</ResponseField>

<ResponseField name="joined_at" type="string">
  ISO 8601 timestamp of when the staff member accepted their invitation and joined the shop.
</ResponseField>
